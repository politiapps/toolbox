# Cross-platform audit — 20 September 2026

Scope: source review of shared task logic, Obsidian and Android task flows,
Android storage/widget integration, UI/navigation, build pipeline, plus the new
shopping feature. This is a source and automated-test audit, not a full native
or Obsidian runtime certification. No personal vault was opened or changed.

## Fixed in this change

| Finding | Fix |
| --- | --- |
| Category views show completed tasks from unrelated categories in both apps | Apply the selected category tag to the completed section in both renderers. |
| Overlapping reads can repaint older task content after newer content | Render generation checks in Android and Obsidian; closing the Obsidian view also invalidates pending reads. |
| Android retains the previous vault's “plugin configuration found” flag | Reset it before each configuration read; mirror plugin configuration again on foreground. |
| Valid JSON `null` configuration causes property access errors | Validate the parsed configuration object before reading sections. |
| Android vault change paints settings over a list screen while navigation state says list | Let the vault-switch operation own the destination render. |
| Native file creation always requests Markdown MIME, including JSON | Request application/json for JSON filenames. |
| No CI guard for shared regressions or Android web compilation | Add push/PR checks for tests and both app builds. |
| Shopping feature would otherwise duplicate platform UI and behavior | One shared DOM surface, shared theme-aware styles, shared domain and persistence rules, and integration tests. |

## Remaining findings, in priority order

1. **High — overlapping task writes can lose changes.**
   `src/taskView.ts` append/replace/structural operations and
   `apps/android/src/taskService.ts` independently read and overwrite whole
   files. Two rapid mutations can read the same original, with the second write
   discarding the first. The native widget is a further independent writer.
   Move task mutations behind a per-file queue and use Obsidian's atomic
   processing API where available; native writes need coordinated locking and
   conflict handling. Read-before-write alone does not make a transaction.

2. **High — task identity is ambiguous for duplicate lines.**
   `packages/task-core/src/taskParser.ts:findTaskByRaw` returns the first match;
   Obsidian `replaceLine` also uses the first matching line. Editing/deleting the
   second identical task can affect the first, including a different subtree.
   Introduce durable IDs or disambiguating context with conflict rejection,
   including the native widget cache. A simple stored line number is unsafe
   after an external insertion.

3. **High — widget completion diverges from app completion.**
   `WidgetFile.java:completeTask` searches for a substring rather than an exact
   line, so a cached short task can match the start of a longer edited task.
   It also completes recurring tasks without generating their next occurrence.
   Route widget actions through the canonical mutation engine (or implement
   and test equivalent exact-line and recurrence handling). Storage IO also
   runs directly in the broadcast receiver and should move off its main thread.

4. **Medium — Android modal accessibility/lifecycle gaps.**
   `apps/android/src/ui/dom.ts:openModal` lacks dialog semantics, focus trapping,
   focus restoration and Escape handling. Closing one of multiple sheets clears
   the body's modal-open state even if another remains. Use a modal stack with
   shared focus and dismissal behavior; verify TalkBack and hardware Back.

5. **Medium — file-read errors lack a recovery surface.**
   Android startup and task rendering await storage without an in-app error/
   retry view. A revoked grant or provider error can leave a blank/stale screen.
   Provide a recoverable error state with retry and vault relinking; distinguish
   a missing file from unavailable storage. Shopping already reports errors
   inline and offers Refresh.

6. **Medium — calendar fidelity remains limited.**
   `src/calendar.ts` treats TZID times as wall-clock and lacks RECURRENCE-ID
   overrides (also documented in the existing architecture). Travelling across
   timezones or moved recurring events can show incorrect times/duplicates.
   Add timezone/override fixtures before changing this separate feature.

7. **Medium — native releases are not covered by the new web checks.**
   `apps/android/android/app/build.gradle` still has versionCode 1/versionName
   1.0 independently of npm/plugin versions. Add native build/device CI and an
   explicit versioning/release process before distributing app updates.

8. **High — development-tool dependency advisories remain.**
   `npm audit` initially reported 10 findings. A non-breaking `npm audit fix`
   updated five packages, leaving 5 reported findings (1 critical, 1 high,
   3 moderate) in the Vitest/Vite/esbuild toolchain and transitive packages.
   npm proposes breaking toolchain upgrades for the remaining findings. Plan
   those upgrades with test/build compatibility checks; this change does not
   claim a clean dependency audit. The advisories concern development/test
   tooling; the audit output alone is not proof of a production-app exploit.

## Shopping boundaries

The new list lives separately from existing `#shopping` tasks; there is no
implicit migration. Classification is an offline dictionary with manual
fallback, not comprehensive grocery recognition. The filename and standard
category order are fixed defaults; custom stores/categories are user-entered.
Refresh pulls external changes without discarding an in-progress form. Local
queued writes and pre-write conflict checks do not guarantee atomic writes
across sync clients. JSON history is retained indefinitely; there is no history
purge or shopping widget yet.

## Validation

- 103 passing tests across eight files: shared task/shopping domain, shared
  shopping DOM integration, and Android regressions.
- Android regression tests for category completion filtering and stale renders.
- Obsidian TypeScript/production bundle and Android TypeScript/Vite build.
- Native compilation unavailable here: `java -version` reports no Java runtime.
- Obsidian rendering and Android SAF/provider/device behavior require runtime
